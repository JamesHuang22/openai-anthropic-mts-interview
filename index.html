OpenAI PART I

核心特征：刻意远离 LeetCode 套路题，考的是「在 CoderPad 里从零写出生产质量代码」的速度与完成度。编码分是硬门槛。

完整流程

已确认
  1. 简历筛选

    竞争极其激烈。看重规模与影响、量化成果；基础设施团队看重系统类工作。

  2. Recruiter 电话 — 30–45 分钟

    背景、「Tell me about yourself / 过一遍简历 / Why OpenAI?」，以及在招团队、时间线。不只是走流程：Land the Lab 2026 年 10 月的分析指出，这一轮会问你对 AGI 和 AI 安全的看法，「AI 安全问题答得弱，流程可能就此结束」——把它当成真正的关卡，通话前先准备好自己的安全观。

  3. Hiring Manager 电话 — 20–30 分钟

    背景、职业目标、与团队相关的技术、过往系统与权衡；研究/应用岗会深挖某个研究产出或项目。（顺序因团队而异，有些流程 HM 在后面跑最终行为轮。）

  4. 技能评估 — 三种形式之一（无统一标准）

    ① CoderPad / HackerRank 现场编码或结对编码（最常见）；② 系统设计 screen（资深岗更常见）；③ HackerRank / 私有仓库 take-home（因团队而异，见下文）。

    2026 年 10 月新变体：多位候选人报告是两场 60 分钟 screen——一场编码、一场设计，有时同日进行；另有一位 Glassdoor 2026 年 10 月候选人报告单场 90 分钟 CoderPad，编码 + 简短设计讨论合并。

  5. Final loop（默认虚拟，SF 可选现场）— 4–6 小时，4–6 位面试官，1–2 天
    • 编码 #2（从零搭建，规模大于 screen）
    • 重构 / 调试轮（资深流程尤其常见，见下文）
    • 系统设计（若已有 design screen，这里是第二场、更深）
    • 项目展示 / 复盘 — 2026 年 10 月报告为 45 分钟：几页 slides 讲 1–2 个你主导的项目，随后快速追问 ownership、考虑过的替代方案、「放大 10 倍会怎样」。资深/Staff 候选人应默认有这一轮。
    • 与资深/HM 的行为面（领导力、ownership）
    • 跨职能协作行为面（部分流程）
  6. 决策、定级、团队匹配 — 约 1 周，最长约 2 周

    定级与匹配都在最后进行；外部候选人多落在 L4/L5，资深校准 L5/L6。决策阶段可能要求两位推荐人（含一位 manager）。相对原 title 被降级很常见。有竞争 offer 截止日期会加速——尽早告诉 recruiter。

各阶段考什么：recruiter = 动机 + 安全/使命观 + 团队契合；screen = 独立实战编码（IGotAnOffer 明确：面试官需要给出多次实质性提示即判 fail）；design screen = 具体的 API + 数据 schema；onsite 设计 = 规模化、重试/幂等、生产正确性；项目展示 = 真实的 ownership 深度（强 coder 常因讲得太浅挂在这里）；行为/HM = ownership、模糊性、冲突、使命感。

2025–2026 的变化

· 编码 screen 与 onsite 编码禁用 AI、禁用自动补全，可查文档（Land the Lab，2026 年 10 月，n=144）。练习时请关掉补全。
· 单一来源 / 新兴 部分流程出现 beta 版 「agentic coding」轮：用 AI 编程 agent 处理一个手工搞不定的大代码库——这是唯一明确允许用 AI 的轮次（SupaCV 2026 playbook）。不要默认会有，问 recruiter。
· 早期职业候选人可能在 screen 之前先做一个限时在线测评。

编码题：题型全景

已确认 刻意远离 LeetCode：题目是生产形态、多部分递进（3–5 个部分）、代码量大——「全程都在打字」。生产质量计分：结构、命名、边界、测试。Python 是最稳妥的语言（面试以 Python 为主，多位候选人称 C++ 让他们丢了时间）。一个写完并测过的解法胜过一个没写完的聪明解法；screen 里干净地完成 2–3 个部分是报告中的通常过线标准。

重构 / 调试题（资深流程）已确认

  • 给一段有问题的现成代码，在时间压力下重构并修好。候选人警告：光读代码就烧掉 15 分钟很容易——尽早形成假设（theory）。
  • 报告实例：一个 O(n²) 的日志文件解析器——debug 它、优化复杂度、在不改变行为的前提下重构得更清晰，并说明你会如何测试这些改动（IGotAnOffer）。

ML / AI 专项

通用 SWE MTS 已确认：不要求你推导 transformer。但要求你能推理模型驱动的系统：LLM API、流式、token 计数/预算、限流、批处理、概念级 KV cache、GPU 负载权衡、把 evals 与安全层当作系统组件。「非 ML 岗位也用得上」。一位拿到 offer 的 Glassdoor 候选人说，真正帮到他的是用 OpenAI API 做了 1–2 个带测试的小东西，而不是刷 LeetCode。

ML 方向 MTS / Research Engineer：从零写 ML 代码是真的（2026 年 10 月最高频 12 道编码题中有 4 道是 ML 编码，尽管 ML 编码在 84 道里只占 8 道）：

  • 找出一个小型 Transformer 训练脚本里被埋的 bug（onsite 编码，最近报告 2026-10-02）
  • 找出有噪声的标注员，剔除后重训分类器
  • 带 autograd 的矩阵乘积扫描 + 手写反向传播
  • 把向量化最近邻分类器实现为一个线性层
  • 找出并修复一个约 300 行 transformer 实现里的 bug，然后加上 KV caching（DesignGurus）
  • 在一个会丢消息的通信信道上实现 all_gather
  • 解释 layer norm 为何提升训练稳定性；transformer 如何学到长程依赖
  • 推导一个概率函数的期望迭代次数

行为面 / 文化 / 价值观

已确认 报告过的题目：

  • 「Why OpenAI?」——会被问多次，包括「Why this lab, and not another one?」（HM 轮：「Why OpenAI over the other labs?」）
  • 「如果被要求在没有安全测试的情况下上线，你会怎么做？」（Land the Lab，2026 年 10 月——报告为 HM/行为面题目）
  • Recruiter 阶段的 AGI/安全观；「你对 AI 走向的看法，我们将如何使用它？」「你认为 AI 会在哪里出错、被滥用？」「使命的哪一点吸引你，它与你的工作如何连接？」
  • 「你如何看待 AGI 的社会影响？」「你对开放研究与商业化之间平衡的看法？」（后两题来自一篇候选人经历帖，dev.to——单一来源）
  • 「你如何在速度与安全约束间平衡？什么情况下你会在高管压力下推迟上线？」（经 Aced PM 指南报告——PM 风味，主题相同）
  • 标准题但追问很硬：介绍自己；最自豪的项目/成就；走一遍你主导过的大型技术项目；一个特别复杂的技术问题及你的解法；一次艰难的技术权衡；无职权影响决策；一次犯错；冲突的优先级管理；与跨职能伙伴的分歧；与 manager 的分歧；与利益相关方沟通困难

OpenAI 的淘汰原因

  • 编码挂掉不可挽回（见上方引文）；需要多次实质性提示 = 即使做出解法也判 fail（IGotAnOffer）。
  • 「NeetCode 对这个流程基本没用」（一位拿到 offer 的 Glassdoor 候选人）——只刷 LeetCode 是最常见的备考错位。
  • 重构轮：读太久而不形成假设。
  • 项目展示：ownership / 权衡 / 规模讲得太浅。
  • 安全/AGI 回答弱或套话——可能在 recruiter 电话就结束流程。
  • 强信号：从第一个部分起就是带测试的生产质量代码（让后续扩展便宜）、独立解题、DDIA 级别的分布式系统深度、以及一个具体、有推理的「Why OpenAI」。

Anthropic PART II

核心特征：题库小而出名，所以面试官会在轮次中途改题（perturb）来测你是否真会做而不是背过。过度设计是被点名的失败模式——价值观「Do the simple thing that works」在编码轮里是被字面执行的。而真正的头号杀手是独立的文化/价值观轮。

完整流程

已确认
  1. 申请 — 含书面「Why Anthropic?」

    许多岗位的申请里就有一道书面题（强回答约 200–400 词，被高度重视——ChillInterview 基于当前在招岗位的指南）。注意顺序：CodeSignal 可能在 recruiter 电话之前就发来。

  2. Recruiter 筛选 — 15–30 分钟

    背景、动机、岗位契合。从第一分钟就带使命/价值观色彩（FrontierLoop 综合 60+ 份报告）——「前沿 AI 很 exciting」式的泛泛回答在这一关就会被过滤。题目：介绍自己；为什么偏偏是 Anthropic？为什么这个岗位？过一遍简历；3–5 年职业目标。

  3. 在线测评 — CodeSignal，90 分钟（第一道技术过滤）

    一个项目、4 个递进关卡（有候选人报告 6 部分变体——以你的邀请为准）。必须通过当前关卡的测试才能解锁下一关，每关都是在同一份代码上扩展。题族与评分冲突见下文。据 FrontierLoop，referral/资深候选人常被豁免——单一综合来源，官方未证实。

  4. 现场技术 screen — 约 55–60 分钟

    与工程师在 CodeSignal/Colab（有人报告 Replit）+ Google Meet 中实战实现。基础题约占 ⅓ 时间，其余是规模、IO-bound vs CPU-bound、并行化的追问。可查文档/搜索；不可用 AI（见政策一节）。

  5. Hiring Manager 筛选 — 约 60 分钟

    深挖你的背景：走一遍职业经历，然后逐项目追问——为什么那个决策？权衡？会怎么做不同？你怎么知道它有效？同时看团队契合与早期文化信号。非 ML 背景：大方承认，讲清转型故事（IGotAnOffer）。

  6. 虚拟 onsite — 分两天进行（显著特征），通常 4–5 轮 × 约 55 分钟
    • Loop 1：编码 + 系统设计。Loop 1 挂了，Loop 2 直接取消（Miami/InterviewQuery 汇总；Land the Lab 亦认同：「第一天 onsite 表现弱，第二天会被取消」）。
    • Loop 2：HM 对话（若还没做）、项目深挖（约 20 分钟展示一个你端到端 own 的项目——候选人报告用 Notion——然后约 40 分钟追问决策、跨团队协调、权衡）、部分流程有第二场编码，以及文化/价值观面（见下文）。
    • 部分流程在技术 loop 里包含 LLM 与提示工程轮（见 ML 一节）——IGotAnOffer 把它列为标准技术轮，其他指南认为是团队相关。问 recruiter。
  7. 背调 + 团队匹配 — 并行进行，2–4 周以上，有时 6–8 周

    背调在周期进行中就查，有时甚至在终轮期间（InterviewQuery 候选人报告：三位推荐人在不同时点被联系，包括终轮进行时）。宽口径岗位是先对着一个通用 bar 面试，再按你的兴趣/经验 + 组织需求匹配团队（Claude.ai、API、企业版、agents、平台、infra）。候选人可能在通过全部轮次后，因没有坑位在匹配阶段被拒（Implicator / interviewing.io 报道）。任何阶段被拒都不给反馈；12 个月后可重新申请（或有实质变化时更早）。

  8. Offer 与谈判

    谈判是被预期的（FrontierLoop）——这与一个源自 Jobright/Blind 的「Anthropic 不谈判」说法来源冲突；较新的综合来源说可以谈。可执行结论：不要假设第一份 offer 是最终版，也不要过早透露当前薪酬/手头 offer。

时间线（诚实的冲突区间）：IGotAnOffer 称 4 周到 3 个月以上（Glassdoor）；其他指南称快时 3–4 周全程走完；Land the Lab 数出 8 个接触点。差异主要来自团队匹配。

工具/形式事实（官方职业指引转引）：全部面试走 Google Meet；现场编码在 CodeSignal / Google Colab；系统设计常打字写进共享 Google Doc，而不是画图（Land the Lab：设计评分看 API、数据模型、请求流、处理给定负载、≥1 个失败场景——全用文字）。默认 Python。

2025–2026 的变化

· AI 使用政策在 2025 年中反转并明确化（Fortune，2025-07-21）：申请材料——先自己写初稿，然后可以用 Claude 润色；备考——明确鼓励用 Claude；take-home——除非说明，否则不用 Claude；现场面试——除非面试官说可以，否则不用 AI。详见下文政策一节。
· 单一来源 / 新兴 部分 2026 流程新增一轮用 Claude Code 写代码并做 code review——那一轮预期使用 AI（Land the Lab）；其余 4 个技术轮默认仍禁 AI。
· 申请阶段检测：据 IGotAnOffer，Anthropic 会用 LLM 检测 CodeSignal 代码是否「为通过测试而工程化，而非真正解决问题」——写真实、通用的代码，不要写 test-shaped 的 hack。

编码题：CodeSignal OA 题族（90 分钟，4 关）

已确认
  1. 内存数据库——报告频率最高。详细候选人记录（Linkjob，2026）：记录以字符串 key 索引，每条记录是 field→value 的字符串对。第 1 关：SET <key> <field> <value>、GET、DELETE（含删字段）。后续关卡（综合各指南）：按 field/value 前缀过滤的 SCAN、带时间戳的 TTL 过期、备份/恢复与持久化、压缩。

  2. 银行系统——开户 + 余额查询 → 转账 → 带过滤的交易历史 / 消费排名 → 利息与时间相关逻辑、返现、账户合并；边界：负余额、退款、超时。

系统设计题

形式 已确认：约 55 分钟；常在共享 Google Doc 里进行（用文字写 API/数据模型/失败场景）。报告的 29 道设计题中 21 道是 AI 系统/ML（Land the Lab）。两个 Anthropic 特色：

  1. 先算账：尽早做容量/GPU/带宽的数学估算并让它驱动设计；然后保持简单——过度设计是报告最多的设计失败（FrontierLoop，多来源原话一致）。
  2. 面试官主导节奏（单一指南但很详细——Coditioning）：面试官可能给话题限时、在数据模型 → 失败模式 → 一致性之间跳来跳去并主导顺序。僵硬的顺序框架会崩；模块化思考，用微复盘（「给定 X，我选 Y 因为 Z；代价 W 被接受因为……」），并明确点出还没覆盖的地带。
  3. 安全/运维是一等评分项：滥用防范 + 限流的落点、什么记日志 vs 什么为隐私脱敏、误用/对抗性使用、事故响应 + 回滚——权重高于一般大厂（Coditioning 量表综合）。

ML / AI 专项

Anthropic 明确不要求 SWE MTS 有 ML 背景：其技术人员中约一半入职时没有 ML 经验（Anthropic 职业页面，几乎每份指南都引用）。门槛是 AI 原生的工程判断力，不是研究深度。

LLM 与提示工程轮（许多 SWE 流程里有）

IGotAnOffer 把它列为标准技术轮，在 Google Colab 里进行；面试官测你是否理解 LLM 如何工作、在哪里会失败、以及如何绕开这些限制来设计。报告过的任务：

  • 为具体用例设计有效的 prompt；推理一套系统化的提示工程方法
  • 构建高效调用 LLM API 的系统——token 管理、限流、成本模型
  • 设计多个 LLM 调用相互协调的多步推理系统
  • （Applied-AI track，不同岗位但能说明风味：检索打分器、token 预算分配器、工具调用编排器——「做一个能跑的东西，并推理它的失败模式」）

通用 SWE 应能讨论的概念（由设计轮 + LLM 轮的深度推断，设计轮深度已确认）

  • Token 与上下文窗口预算（发送前计数、预留输出预算、长对话的摘要/钉选策略）
  • 连续批处理；KV cache（存什么、为何 decode 是显存受限、显存随序列长度 × batch 的增长）
  • Prefill vs decode；用流式掩盖延迟
  • RAG 管道形态（切分、embedding、向量检索、混合检索、引用/溯源）以及何时不用 RAG / 何时改微调
  • Evals（如何超越「肉眼看」来知道系统有效）；护栏（直接/间接 prompt 注入、PII 处理、输入/输出过滤、红队）
  • 模型路由/降级与成本-延迟权衡
ML 方向 MTS / Research Engineer（对照，更深）
  • 「解释 Transformer 的架构——关键组件及为何重要」
  • 「你会如何为推理延迟优化一个模型？」（量化、蒸馏、硬件加速）
  • 设计带容错的分布式训练管道
  • numpy 式数组操作，偶尔手算梯度
  • 研究头脑风暴（「你会如何检测语言模型的幻觉？」/「设计一个实验，检测模型是在欺骗还是只是答错」）
  • 研究展示 / 论文深挖

来源：Jobright · Sundeep Teki 研究岗指南（研究 track 指南，其 SWE 论述较薄，仅用于 ML track 对照）

行为面 / 文化 / 价值观——Anthropic 的定义性轮次

把它当技术轮来备考。独立的文化/价值观面（约 60 分钟，有时两位面试官——一位提问、一位旁听；面试官可能来自任何部门、非技术背景，低分实际上就是一票否决）。Bloomberg Businessweek（2026 年 5 月）+ interviewing.io 创始人：据 Anthropic 的 recruiter，这是「大多数候选人挂掉的地方」；一位 recruiter 对某候选人直言，有人「技术面表现非常好，却因为行为面被拒」。候选人形容它「几乎像心理治疗」——追问你的感受，深挖好几层。预制 STAR 故事是最常见的挂法；脚本化回答和奉承都会反噬；被一个好论点说服、更新自己的立场，正是这一轮在测的行为。

已确认 报告过的题目：

  • 「你持有哪些不寻常的信念，你如何在不舒服的场合为它们辩护？」——Daniela Amodei（联合创始人/总裁）在 2025 年一档播客中亲自描述的测试，Bloomberg 亦有印证。来源：Becker's / Bloomberg
  • 「讲一次你与工作产生道德冲突的经历。你和谁谈了？他们说了什么改变了你的想法？」/ 变体：「讲一次你做了一件违背自己价值观的东西」
  • 「你对 Anthropic 的使命或方向有什么担忧 / 批评？」——不是陷阱；全盘同意才是弱答案。一个具体、论证充分、无敌意的异议，得分高于附和。
  • 「你如何在交付速度与安全/安保之间平衡？」
  • 「讲一次你收到负面反馈的经历——你如何处理？」
  • 「描述一次你与 manager 意见不合，后来改变了想法」
  • 「在高风险环境中部署 agentic AI 系统有哪些伦理风险？」
  • 「讲一次你做出安全优先的决策，即使意味着取舍」
  • 「讲一次技术误判导致项目延期。你学到了什么？」
  • 「描述一次你与同事的技术分歧。你如何解决？」
  • 「如果你在项目中途意识到它其实不可行，你会怎么做？」
  • 「讲一次你对一个不同意的技术方向提出反对」
  • 全程预期负面框架的追问：你不喜欢的团队、你觉得受限的策略、难以接受的反馈（Miami 汇总）
  • 单一报告（Blind，经 Hello Interview 转引）：被问是否愿意接受 Anthropic 股价归零以换取使命的推进——把取舍落到个人身上
  • 每一位面试官、每一轮，都会问某种版本的「Why Anthropic?」

HM 轮题目：项目走查 + Why/权衡/会怎么做不同的追问；「你个人 own 了什么？」；一个 0→1 系统或大型迁移；你建过的技术上最难的系统。

Anthropic 公开陈述的价值观（用自己的话准备）：Act for the global good；Hold light and shade；Be good to our users；Ignite a race to the top on safety；Do the simple thing that works；Be helpful, honest, and harmless；Put the mission first。值得真读的一手材料：Core Views on AI Safety、Responsible Scaling Policy、Constitutional AI 论文、Dario Amodei 的文章（recruiter 可能在 onsite 前发安全阅读材料）。

Take-home / 实战练习 与官方 AI 政策

核心 SWE MTS 通常没有多日 take-home——90 分钟 CodeSignal 就是那个限时实战练习（不要混淆两者）。Take-home 出现在：

  • Research Scientist / Research Engineer：约 48 小时窗口的问题集/数据集，或约 5 小时限时项目（API 探索 / 模型评估）。评审看推理过程：一份展示「试了什么、什么失败了及原因、多给时间会做什么」的 write-up，胜过一份把这些藏起来的干净 write-up（FinalRoundAI 综合）。
  • Performance Engineer：专门的 2 小时限时 take-home——优化一个核心 kernel（循环展开、显存合并、算子融合；GPU kernel 风格）。这一岗允许 AI 工具；一位候选人报告做到约 8× 提升、需 >600/1000 晋级（Jobright 引 1point3acres——单一来源细节，数字谨慎看待）。
  • Applied AI Engineer（相邻岗位）：3–4 小时延展现场搭建 / take-home——按一个虚构客户简报做一个小型 Claude 驱动的应用；按已交付行为、API 卫生、处理模糊性的能力评分（GetPerspective 综合）。
  • Code review 实战：上文的设计文档评审，就是 SWE 流程里的评审练习。

官方 AI 使用政策（2025 年中更新）已确认

  • 申请材料：先自己写初稿，然后可以用 Claude 润色。
  • 备考：明确鼓励用 Claude（「用 Claude 研究 Anthropic、练习你的回答、为我们准备问题」）。
  • Take-home：「除非我们另行说明，不要用 Claude 完成。」
  • 现场面试 / CodeSignal：除非明确说明，不得使用 AI 协助——包括 Claude、ChatGPT、代码生成和 AI 自动补全。技术面试中查普通文档/网页是允许的。

来源：Metaintro（汇总 Fortune 2025-07-21 报道） · Hello Interview

Anthropic 的淘汰原因

  • 文化轮是第一过滤器——排在任何技术轮之前。
  • 过度设计（编码和设计轮）——违背「do the simple thing that works」。
  • 现场轮沉默写代码；不讲述走过的死路。
  • 泛泛的「Why Anthropic」（「有意思的 AI 问题」「Claude 很 impressive」）——recruiter 主动过滤使命的具体性：引用 Responsible Scaling Policy、Constitutional AI、可解释性，并把它们连到你的系统经验（例如把 agent 安全当作软件架构问题：隔离、最小权限、可观测执行、爆炸半径限制）。
  • CodeSignal 有速度没扩展性——第 1 关图快写出脆弱结构，到第 3 关必须重写；或者反过来，把前面关卡打磨到完美然后没时间了。
  • 团队匹配停滞——全部通过却没有坑位；保持其他流程在跑，清楚表达团队意向，提前备好推荐人。
  • 强信号：从简单开始 → 让它跑起来 → 吸收新约束 → 说出权衡 → 加固（ChillInterview 对反复出现的模式的总结）；先算账的简单设计；真诚、具体、带怀疑的价值观回答（包括对 Anthropic 的真实批评）。

备考计划（按优先级）

为「Amazon SDE II、6 年分布式系统」画像定制。你的不公平优势：生产级分布式系统、事故处理、规模、ownership 故事。你的差距：无自动补全/IDE 时从零写 Python 的速度、LLM 系统词汇，以及（对 Anthropic）价值观轮的深度。以下顺序按「失败率 × 差距」排序。

P0 · 先做这些（失败率最高的项）

1. Build-and-extend 编码：Python、限时、关掉自动补全，在 CoderPad/CodeSignal 式编辑器里练

这是两家共同的核心测试，也是与 Amazon 流程最大的风格差异。按顺序练到每题能在约 50–60 分钟内带测试完成：

  • 内存 DB/KV：SET/GET/DELETE → scan/过滤 → TTL → 持久化/压缩（同时服务 Anthropic OA 与 OpenAI 的 KV/LSM 变体）
  • 可恢复迭代器（列表 → JSON 文件 → 多文件 → 嵌套）
  • 银行/账本系统，含一个乱序事件 + 过期规则的 GPU-credit 账本变体
  • 带符号链接的 cd；带环检测的电子表格
  • 并发 Web 爬虫（有界、去重、失败处理）——然后把其他每个解法都做一遍并发版
  • 文件去重（大小 → 哈希）；调用栈 profiler（从采样找最久的函数）；函数缓存 + 持久化

练习规则：先让第 1 部分能跑再优化；边写边补测试；全程出声讲解（Anthropic 现场轮惩罚沉默）；写完后给自己加一个 surprise 需求，不重写地吸收它。

2. 一个项目深挖，武器化

选你最强的 Amazon 系统（端到端 own、有事故、有硬权衡）。准备两个版本：20 分钟的 Anthropic 版和 45 分钟带 slides 的 OpenAI 版。演练追问：你个人 own 了什么 vs 团队？为什么 X 不选 Y？指标——你怎么知道它有效？那次事故，诚实讲。10 倍规模先坏哪里？会怎么做不同？在这一项上讲得浅，会让强 coder 在两家都挂掉。

3. 你的价值观/安全立场——写下来、具体、能扛 3 层追问

  • Anthropic 版：读 Core Views on AI Safety、Responsible Scaling Policy、Constitutional AI 论文摘要。准备好：一个真诚的认同、一个对 Anthropic 方向的真诚批评、一个工作中的道德冲突故事（和谁谈了、什么改变了你的想法）、一个你捍卫过的不寻常信念、一次改变想法的经历、一个你真实做过的安全优先取舍。练习在被好论点推动时当场更新自己的观点。
  • OpenAI 版：对 AGI 时间线/影响、开放研究 vs 商业化、滥用风险的成型看法，以及对「如果被要求无安全测试上线你会怎么做？」和「为什么是 OpenAI 而不是 Anthropic/DeepMind？」的直接回答——两个答案不能互换着用。
P1 · 系统设计，实验室风味（你的强项——调风味，不用重学基础）

4. 五道题端到端练，每道 55 分钟，前 10 分钟先算容量账

(a) 推理批处理系统：单 GPU → GPU 集群（Anthropic 标志题）；(b) 带 RBAC 的 LLM 企业搜索（OpenAI 标志题）；(c) 100K rps 的 token 生成 / LLM 推理服务（连续批处理、KV-cache 显存预算、prefill vs decode、准入控制、流式）；(d) Claude/ChatGPT 聊天服务（历史、流式、多问题线程）；(e) 一道经典题（webhook 投递、限流器或 GitHub Actions）——OpenAI 仍然重考经典题。

5. 至少用 Anthropic 的形式练两次

打字写进文档、接受面试官打断/主导节奏，外加一次设计评审练习（批判一份故意有缺陷的推理批处理设计：失败处理、过载保护）。

6. LLM 系统速查表——要能用，不是能背

token/上下文预算、KV cache、连续 vs 静态批处理、speculative decoding（概念）、量化（FP8/INT8/INT4 权衡）、PagedAttention（概念）、SSE vs WebSocket 流式、429/Retry-After + 公平队列、语义缓存、RAG vs 微调的决策、evals（离线集、LLM-as-judge 的局限、回归门禁）。

P2 · 通用岗的 ML 素养（以天计，不以周计）

7. 一小时讲清 Transformer，工程师级别

分词（BPE、贪心最长匹配）、embedding + 位置、自注意力、KV cache 为何成立、layer norm 的作用、prefill/decode。能白板画一次前向传播并解释长程依赖。在两家 API 上各做一个小东西（一个带 evals 的、基于自己文档的 RAG + 一个懂 token/限流的客户端）——一位成功的 OpenAI 候选人称这才是真正帮到他的备考。

8. 仅当瞄准 ML/infra MTS track 时

从零 PyTorch/NumPy：注意力、一个 transformer block、简单算子的手写反向、KV-cache 实现、transformer 捉虫练习、all_gather 语义。通用 SWE 流程不要把时间花在这里（ML 编码在 OpenAI 报告编码题中只占 8/84）。

P3 · 真正影响结果的后勤

9. Recruiter 电话上问清

确切的轮次列表与顺序；现场还是 take-home；是否有 design screen 之外再加 onsite 设计；你的轮次的 AI 政策；语言/环境（CoderPad vs CodeSignal vs Colab）；你在按什么级别被 loop。两家的流程都变得太厉害，不能盲备。

10. 提前备好推荐人

在 onsite 之前就选定并打好招呼两位推荐人（一位是 manager）——Anthropic 在周期中就查；OpenAI 可能在决策时要。尽早告诉两位 recruiter 你的竞争 offer 截止日期（两家都会加速）。

11. 两个「Why」各练到 90 秒

实验室专属、且彼此不同——把 Anthropic 的答案用在 OpenAI（或反过来），是两家 recruiter screen 都点名过的失败方式。

建议节奏（约 4 周，兼职）

第 1 周P0.1 编码题族 1–3 + 开始 P0.3 的阅读
第 2 周P0.1 题族 4–6 + P0.2 项目深挖
第 3 周P1 设计题（5 道 + 1 次评审练习）+ P2
第 4 周限时全真模拟（一场 OpenAI 形态：编码 + 重构 + 设计；一场 Anthropic 形态：90 分钟 CodeSignal 模拟 + 价值观 mock）、价值观答案压力测试、后勤确认
